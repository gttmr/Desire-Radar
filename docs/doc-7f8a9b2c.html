개인 프로젝트 상세 소개

Desire-Radar

거창한 플랫폼이라기보다 세상에서 벌어지는 일들을 모아 보관해 두고 추론의 증거로 지속 재조합하는 시스템입니다. 투자 관련 인사이트와 검증 엔진은 이 수집 구조 위에 구축된 초기 실험입니다.

아키텍처 확장 원칙: Preserve Facts, Derive Separately

자료 수집, 전처리, 판단 로직을 한 곳에 묶지 않습니다. 수집기가 원본 데이터를 명확히 "근거(Evidence)"로서 보존하며, MCP 오케스트레이터의 에이전트들이 그 근거 위에서 다단계 추론(Triage, Debate, Verification)을 진행하여 결과를 만들어냅니다.

Collector: 데이터 수집 및 적재의 고도화

  • Python 개발. 다차원의 Pull / Push / Human / 파생 소스 통합 Ingestion 제공.
  • 수집 채널 및 Registry의 티어/분류 동적 관리 및 원본 증거 보존.
  • 배치 CLI LLM 분석으로 Entity Cluster 단위 생성, Triage 최적화 수행.
  • 크롤러뿐만 아니라 Reddit, Polymarket, X 등 복합 소스의 상태 증거를 보존.

MCP Orchestrator: 투자 판단 및 결론 도출 엔진

  • TypeScript 기반 Agentic 오케스트레이터로 봇 역할과 완전 분리 설계.
  • Triage → Debate → Research-loop → Verdict 의 다단계 토론-검증 모델.
  • Provider, Model의 API 불안정 대응을 최우선한 CLI Session/Adapter 래핑 디자인.
  • 가장 고비용/고품질의 모델 자원은 최종 판단(Verdict) 단계에만 집중 투자.

정보가 관점이 되고 결론으로 수렴하는 흐름

채널 소스 수집(Registry) → 원본 증거(Raw Snapshot) 보존 → 데이터 번들링 및 후보 생성(Bundle) → 도메인 오케스트레이션(Triage & Debate) → 자산 맵핑 및 우선순위 식별(Normalize) → 투자 리포트 결론 생성(Verdict Artifact)

↑ 검색 시스템이 문서를 가져와 인덱스를 구축하고 서빙하는 그 단계를, AI 시대에는 멀티 에이전트들이 "이해"하여 증거로 축적하는 설계입니다.

Python (Collector) TypeScript (Orchestrator) 데이터 파이프라인 (Data Pipeline) MCP 멀티에이전트 협업 체계 도메인 주도 설계(DDD) 관점 CLI Provider Volatility 관리 (Adapter Design) 결정론적 Artifact First 디자인
